# Security Policy

## Supported versions

Security fixes are applied to the latest tagged release. Consumers should pin a
semantic-version tag and review the changelog before upgrading.

## Reporting a vulnerability

Use the repository's GitHub Security tab to submit a private vulnerability
report. Do not open a public issue for suspected credential exposure, PHI
leakage, route-label cardinality bypasses, or release-artifact compromise.

Include the affected tag, Node.js version, framework adapter, reproduction
steps, and impact. Remove credentials, patient data, raw request paths, and
other sensitive production values from the report.

Maintainers will acknowledge the report, assess affected versions, coordinate a
fix and disclosure timeline, and publish a tagged release when remediation is
available.
